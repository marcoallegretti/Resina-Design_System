# Density intent (candidate)

Density is an explicit information-density preference, separate from device class, viewing profile, input capabilities, text scale, and renderer quality. The [environment snapshot](18-environment.md) carries exactly one of `compact`, `standard`, `comfortable`, or `immersive` for each resolution operation. A producer MUST supply the preference. A consumer MUST preserve it and MUST NOT replace it by inferring a mode from a pointer, gamepad, touch screen, window size, or viewing profile. Every mode remains valid with every reported input and viewing profile.

`compact` supports dense, precise workflows. It MAY reduce spacing, row and visual control heights, or redundant labels where the component contract permits. `standard` is the ordinary density intent without a device assumption. `comfortable` supports a more relaxed hierarchy for mixed interaction. `immersive` supports far viewing and high-focus use; a component MAY use larger targets, text, spacing, or focus cues and show less simultaneous information. These are semantic intents, not fixed pixel scales. Numerical mappings belong to the spatial, typography, and component contracts after calibration.

Density MUST NOT reduce an interactive hit region below a component's accessibility minimum. Visual size and interactive hit region are separate. Density MUST NOT silently reduce the user's `textScale`, suppress essential content, or substitute for reduced-motion, reduced-transparency, or high-contrast preferences. Adaptation MAY consider density with available geometry and input capabilities only through an explicit resolution rule; an environment snapshot alone does not select component layout or change its own preference.

The [density vectors](../conformance/environment/density-vectors.json) show all four modes with intentionally mixed viewing and input profiles. They define preservation of the explicit input, not a component spacing scale or an automatic mode-selection algorithm.
