# Headless semantic resolution (candidate, schema 0.1.0)

A [headless resolution request](../schemas/headless-resolution.schema.json) carries one DTCG token document, current material, color, spatial, and typography assignments, and one validated environment snapshot. All fields are required. The nested assignment and environment schemas retain their own versions; the request itself uses `schemaVersion` `0.1.0`. The operation is independent of a renderer and does not select a theme, construct a component, or publish a bundle.

The source MUST be parsed with duplicate JSON member rejection at every depth. The DTCG document MUST pass token structure, group extension, reference, type, and value resolution before semantic bindings are attempted. A request with invalid top-level or nested contracts, an unsupported version, or invalid tokens fails without an output snapshot. The request schema checks the envelope and nested Resina contracts; DTCG token validation remains the token resolver's responsibility.

For a valid request, the [result schema](../schemas/headless-result.schema.json) has `schemaVersion` `0.1.0` and contains every material role's family, every bound semantic color and spatial value, every scaled typography role, the Frost representation selected from the environment, and the minimum hit target. Material family assignments remain independent of Frost's capability fallback. Color and spatial values preserve validated DTCG data; typography uses the [typography resolution rules](11-typography.md). Frost follows the [fallback chain](31-fallback.md), and the hit target follows the [minimum target rule](15-targets.md). The Frost representation is the environment's available choice if a Frost surface is requested, whether or not this assignment currently names Frost. The result schema constrains complete role maps and output value shapes; capability and text-scale decisions are cross-field rules verified by conformance cases.

Color, spatial, and typography binding errors MUST be gathered in that category order, preserving each contract's role order. A failure in any category prevents publication of the entire result. The [request fixture](../conformance/headless/valid-request.json) and [expected resolution](../conformance/headless/expected-resolution.json) cover one complete operation; their shared sample colors and metrics exercise resolution and do not define a theme. The Rust reference exposes `resolve_headless_source` and the `resina-headless` command for file or standard-input requests. The output is a semantic resolution snapshot; component intent, state composition, accessibility layout behavior, and renderer-neutral Resina IR require their own contracts.
