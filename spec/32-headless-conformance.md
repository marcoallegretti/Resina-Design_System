# Headless backend conformance (candidate, 0.1.0)

The [backend cases](../conformance/headless/backend-cases.json) test a headless Resina implementation through a language-neutral command boundary. This checks the [headless request](19-headless-resolution.md) and [result](../schemas/headless-result.schema.json) without importing the Rust reference library. Passing these cases establishes conformance to the covered semantic snapshot operations; it does not establish Resina IR, rendering, accessibility of displayed content, or compatibility at other levels.

The backend command MUST read one UTF-8 JSON request from standard input and process it as `resina-headless -` does. For a valid request it MUST exit with status 0, write exactly one complete result JSON document to standard output, and leave standard error empty. For an invalid request it MUST exit with status 1, write no standard output, and write a nonempty diagnostic to standard error. It MUST reject duplicate JSON members before semantic resolution. Each valid case is invoked twice with identical input to check semantic determinism. Every invocation starts a fresh process; no state may carry between invocations.

Each case is validated against the [case schema](../schemas/headless-conformance-case.schema.json). It starts with the public [request fixture](../conformance/headless/valid-request.json) and [expected result](../conformance/headless/expected-resolution.json). `requestChanges` and `expectedChanges` replace existing values at [RFC 6901 JSON Pointer](https://www.rfc-editor.org/info/rfc6901/) paths. A `sourceText` case supplies exact UTF-8 source text. A `sourceReplace` case replaces one unique substring in the original request text, permitting duplicate-member tests on an otherwise valid request. The checker rejects a change path that does not already exist; changes do not silently create fields. Output must pass the result schema and match the expected document, allowing at most `10^-12` absolute numerical difference per channel or metric. Structural values, strings, booleans, integer constraints, and object membership remain exact. Rejection cases require an error status and no partial result; diagnostic wording is implementation-specific.

Run `python tools/check_headless_backend.py -- <backend-command> -` to check an executable using this protocol. For the Rust reference binary, build `resina-headless` and pass its path as `<backend-command>`. The checker uses the repository's Draft 2020-12 schema dependency and has a 30-second timeout per case by default. An independent backend can use this same runner and public cases without adopting Rust data structures or rendering technology.
