# Focus indicator on a bound surface (candidate, 0.1.0)

A focused [surface intent](20-surface-binding.md) requires a visible navigation cue independent of its body, edge, material, and other active states. The [focus indicator request](../schemas/focus-indicator-request.schema.json) combines one [surface scenario](21-surface-scenarios.md) with the final opaque sRGB `surroundingColor` behind the indicator. The bound state set MUST include `focused`; it MAY simultaneously include selection, validation, activity, availability, interaction, and base states. No state is removed or given visual precedence by this operation.

The [result](../schemas/focus-indicator-result.schema.json) retains the complete bound surface and describes a separate outer stroke following its semantic shape. The stroke is 2 logical pixels wide, with a 2 logical pixel gap from the bound surface's outer edge. It MUST remain visible with blur, transparency, and advanced effects disabled. The ring MUST NOT replace the surface edge, content, or another state channel. A backend must reserve enough paint space to prevent clipping and scale the logical dimensions with its output scale. Shape realization remains governed by [surface shape and form](09-geometry.md); this contract does not prescribe a path primitive.

The resolver first tests the bound opaque `focus` fallback against the supplied surrounding color using [opaque contrast](12-contrast.md). It retains `focus` when the unrounded ratio is at least 3:1. Otherwise it tests the bound opaque `outline.strong` fallback and uses it when the same threshold is met. If both fail, resolution MUST fail with both ratios and no partial indicator. The resolver MUST NOT invent a color, weaken the threshold, or infer the surrounding color from a theme role. All colors MUST be valid opaque sRGB; an unknown or varying surround requires a separate evaluation at each relevant location.

The 2 logical pixel outer stroke and 3:1 threshold are informed by [WCAG 2.2 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html). This local result does not establish full WCAG conformance: actual indicator area, clipping, occlusion, neighboring content, and rendered pixels require backend evaluation. The [public cases](../conformance/states/focus-indicator-cases.json) cover concurrent states, role fallback, failure, and malformed input. `resina-focus-indicator <path|->` reads one UTF-8 request of at most 1 MiB and emits one strict JSON result, or a diagnostic on failure. The [external checker](../tools/check_focus_indicator_backend.py) verifies a backend through this protocol.

The [focus indicator IR](37-focus-indicator-ir.md) composes this color decision with resolved shape, elevation, and physical lighting to produce the complete exterior ring around the swept footprint. It preserves all concurrent states and fails explicitly when current optical treatment geometry is unresolved.
