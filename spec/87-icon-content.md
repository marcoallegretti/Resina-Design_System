# Icon content (candidate, schema 0.1.0)

An [icon content document](../schemas/icon-content.schema.json) describes one icon by Resina metadata. It does not contain artwork. Its `schemaVersion` is `0.1.0`. The `reference` is an opaque namespaced identity of the form `namespace:name`. The namespace is one or more dot-separated segments of lowercase ASCII letters. The name is one or more dash-separated segments of lowercase ASCII letters or digits, with no empty segment. Nothing else, including a trailing line break, is part of a reference. Resina does not interpret the segments, and references compare exactly. A theme or backend icon mapping supplies the artwork for a reference, as a font mapping supplies faces for the [typography](11-typography.md) roles. That mapping, its lookup rules and its diagnostics are separate contracts. Core ships no icon catalogue.

`kind` is `symbolic` or `color`. A symbolic icon is a set of coverage masks, each bound to a semantic colour role. Its `layers` array is nonempty and lists the masks in paint order. The first layer has role `content`, which stands for the content colour role of the part that hosts the icon. Each further layer names a distinct role from `accent.primary`, `accent.secondary`, `accent.tertiary`, `status.error`, `status.warning`, `status.success` and `status.info`, so that it carries a meaning such as an accent or a status mark. A colour icon is consumer artwork that Resina never recolours. It declares no layers. Its `bakedLight` member states whether the artwork contains light or shading. A symbolic icon declares no `bakedLight`.

Measurements are fractions of the square icon box, with the origin at its top-left corner and an edge of 1. The physical size of the box belongs to icon size roles. `inkBounds` is the smallest rectangle that contains the icon's painted coverage. `opticalBounds` is the rectangle that a component aligns and centres in place of the box, so a visually unbalanced shape can sit correctly. The two rectangles may differ in either direction. Each has a nonnegative `x` and `y` and a positive `width` and `height`, and lies within the box: `x + width` and `y + height` do not exceed 1. Numbers are decoded to IEEE 754 binary64, and these sums are evaluated in binary64. A canonical design grid and stroke keylines are not part of this contract; they belong with the size roles, where alignment to device pixels can be measured.

Every icon declares its `direction`; there is no default. `mirror` reflects the icon horizontally about the vertical centre line of the icon box under right-to-left layout. Its bounds reflect with it. `invariant` keeps the same artwork in both directions. `directionalVariants` names an `ltr` and an `rtl` reference. The two are distinct, and neither repeats the icon's own reference. What a variant reference resolves to belongs to the icon mapping. Material light is physical: the [key light](34-key-light.md) and any lighting a backend adds keep their direction when an icon mirrors. A colour icon with `bakedLight` `true` therefore MUST NOT declare `mirror`. It uses `invariant` or `directionalVariants`.

The following are errors:
- missing, unknown or duplicate members, or an unsupported version;
- an invalid reference;
- bounds outside the box or without positive extent;
- a direction without its required variants, or with variants it does not take;
- a layer list that breaks the rules above.

An optional member that is present but `null` is an error, not an absent member. Duplicate JSON members MUST be rejected before conversion to an object tree. An invalid document is not published in part, and it is never replaced by a placeholder icon.

This contract does not define icon size roles, how an icon scales next to a label, the contrast an icon needs against its surface, mapping lookup or resource failure, rendering, or the layout and paint of an icon in a Command. Those need their own contracts and evidence. The [command content](90-command-content-accessibility.md) contract defines the Command content forms that include an icon and their accessible names. The [content vectors](../conformance/content/icon-content-vectors.json) list valid and rejected documents. A case with `schemaValid` `true` and an `error` is valid against the schema but violates a rule the schema cannot express, such as bounds that extend beyond the box. The [duplicate-member document](../conformance/content/invalid-duplicate-icon-member.json) repeats `reference` and is rejected.
