# Frost legibility on a known backdrop (candidate, 0.1.0)

The [Frost legibility request](../schemas/frost-legibility-request.schema.json) checks one selected Frost body, one authored opaque Frost fallback, one opaque foreground, and one known opaque `postTreatmentBackdrop` at the same location. The selected body and representation come from [surface binding](20-surface-binding.md); the fallback is that surface's `opaqueColorFallback`. The caller supplies the foreground color actually used for the content and a finite `minimumContrast` from 1 through 21. Resina does not infer a text size, accessibility criterion, component, or backdrop from a role name. The request is renderer and platform independent.

The selected `portableBody` MUST have alpha strictly between 0 and 1 for `shapedBackdrop`, `regularBackdrop`, or `translucentPigmented`. For `opaqueDimensional`, it MUST be opaque and equal `opaqueBody`. `opaqueBody`, `foreground`, and `postTreatmentBackdrop` MUST be opaque sRGB colors. Unknown fields, invalid colors, unsupported versions, inconsistent representation/body pairs, and nonfinite or out-of-range thresholds are errors. Duplicate JSON members MUST be rejected before object conversion.

For a translucent representation, the resolver MUST composite `portableBody` over the supplied post-treatment backdrop using the encoded-sRGB source-over operation in [the contrast contract](12-contrast.md). It then calculates opaque contrast between the supplied foreground and the composited body. If that unrounded ratio meets `minimumContrast`, it retains the selected representation and body. Otherwise it tests the foreground against `opaqueBody`; if that meets the threshold, it selects `opaqueDimensional` and the authored opaque body. If neither passes, it MUST fail diagnostically without a partial result. An already opaque representation is checked as-is and fails if insufficient. The resolver MUST NOT recolor the foreground, invent an opaque body, or infer a renderer capability.

The [result](../schemas/frost-legibility-result.schema.json) reports the chosen representation and body, the composited opaque body, the unrounded contrast ratio, and whether legibility forced the opaque fallback. The [vectors](../conformance/materials/frost-legibility-vectors.json) cover retention, fallback, both contrast failures, all Frost representations, and invalid input. `resina-frost-legibility <path|->` accepts one UTF-8 request file or standard input; success exits 0 with one strict JSON result and no diagnostic, failure exits 1 with no result and a diagnostic, and usage errors exit 2. The command bounds input to 1 MiB. The [external checker](../tools/check_frost_legibility_backend.py) validates the public protocol, schema, exact results, diagnostics, and deterministic repetition.

This operation requires a known color **after** any backdrop or optical treatment. It neither samples a dynamic backdrop nor proves contrast across an image, motion, or a full surface. It is one local decision in a future surface appearance resolver. The caller must determine the relevant foreground, adjacent color, location, and threshold, then repeat or conservatively aggregate measurements where the backdrop varies. WCAG 2.2 defines [text contrast](https://www.w3.org/TR/WCAG22/#contrast-minimum) and [non-text contrast](https://www.w3.org/TR/WCAG22/#non-text-contrast) criteria; passing this local operation alone does not establish conformance to them.
