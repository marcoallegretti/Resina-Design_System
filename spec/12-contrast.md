# Opaque color contrast (candidate, 0.1.0)

The headless contrast metric accepts two resolved [sRGB fallback colors](07-color-fallback.md) that represent the actual foreground and adjacent background after any transparency, backdrop effect, or other color processing. Both colors MUST be opaque (`alpha: 1`). A translucent input MUST fail; the metric MUST NOT assume a backdrop, silently discard alpha, or treat an authored fallback as a rendered color. If both inputs are translucent, the foreground error takes precedence.

For each sRGB component `c` in `[0, 1]`, linearize it as `c / 12.92` when `c <= 0.04045`, otherwise as `((c + 0.055) / 1.055)^2.4`. Relative luminance is `0.2126 R + 0.7152 G + 0.0722 B` using the linearized components. The contrast ratio is `(Llighter + 0.05) / (Ldarker + 0.05)`. The ratio MUST be returned without rounding. These equations follow the [WCAG 2.2 definitions](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio) for sRGB; the [conformance vectors](../conformance/color/contrast-vectors.json) cover endpoints, the transfer-function boundary, symmetry, and translucent errors.

A ratio alone does not establish accessible text or component contrast. The applicable criterion depends on the displayed content, size, state, and adjacent colors. A material, renderer, or conformance evaluator MUST determine the colors actually seen at the relevant location before using this metric. Dynamic or image backdrops require measurement across the relevant area. The Rust color reference exposes `opaque_contrast_ratio` as a headless calculation and does not choose thresholds or alter colors.

## Known opaque backdrop composition

When a translucent portable color is placed over a known opaque sRGB backdrop at one location, `composite_srgb_over_opaque` calculates the resulting opaque color before contrast evaluation. Input channels are non-premultiplied. For each encoded sRGB channel, with source channel `Cs`, backdrop channel `Cb`, and source alpha `αs`, the output channel is `Cs × αs + Cb × (1 − αs)`. Output alpha is 1. This is the [source-over compositing equation](https://www.w3.org/TR/compositing-1/#porterduffcompositingoperators) evaluated in encoded sRGB, a color space choice made explicitly by this contract. A translucent backdrop MUST fail rather than be treated as opaque. The [compositing vectors](../conformance/color/opaque-compositing-vectors.json) fix transparent, opaque, partial-alpha, and error cases.

The operation does not sample a backdrop, apply blur or treatment, identify adjacent colors, or assert that a renderer uses encoded-sRGB compositing. A caller MUST supply the actual post-treatment backdrop color and use this calculation only when its compositing model matches. For dynamic or unknown backdrops, an opaque contrast claim still requires measured rendered colors.
