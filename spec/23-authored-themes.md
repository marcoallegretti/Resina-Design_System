# Authored fixed themes (candidate)

The [light](../tokens/themes/light.json) and [dark](../tokens/themes/dark.json) sources are authored Resina themes, rather than illustrative conformance palettes. Each supplies every current material, color, spatial, and typography assignment, a Frost pigment strength, and an opaque color fallback for translucent chrome. Their DTCG Resolver Module 2025.10 documents compose the authoritative [foundation source](../tokens/foundation.json) through the explicit external URI `foundation.json` before theme pigments and typography tokens. Compilation MUST receive that URI mapped to the foundation's UTF-8 source text; no network or filesystem fetch is implied by the theme source.

The paired themes use a restrained warm mineral base and a deep blue-black base, with teal as the primary accent, blue as the secondary accent, and amber as the tertiary accent. Cast carries structural surfaces, Frost carries chrome, Elastomer carries interactive controls, and Gel is limited to transient surfaces and feedback. Their explicit role mappings preserve that hierarchy across light and dark conditions. Both themes share one spatial mapping: content gaps use `space.2`, and the control insets step up the foundation scale with density, inline `space.3`, `space.4`, `space.5`, `space.6` and block `space.2`, `space.3`, `space.4`, `space.5` for compact, standard, comfortable and immersive. With the 14 px label at 1.34 line height, one standard line plus block insets is 42.76 px. The sources define semantic choices and do not supply a font file, component layout, edge, highlight, motion, or render-ready paint. A separate [Tier 0 appearance profile](../definitions/tier0-surface-appearance.json) supplies static opaque appearance choices for the [opaque surface IR](36-opaque-surface-ir.md); its integration tests exercise both themes, all families and shapes, RTL, depth roles, 300% text-scale environments, and region containment.

The Rust reference integration test compiles both themes against the authored foundation, resolves baseline, 200% text scale, and zero-capability high-contrast environments, checks selected role assignments and opaque chrome fallback, and verifies that every authored sRGB pigment's hex fallback matches its numeric components.

## Legibility guard

Every authored theme, and every theme [derived from a seed](91-theme-derivation.md), MUST pass the theme legibility guard. The guard reads the compiled theme's [opaque color fallbacks](13-opaque-color-fallback.md) and evaluates 40 named pairs in this fixed order. For each background `surface.base`, `surface.low`, `surface.high` and `surface.chrome`, it evaluates `content.primary`, `content.secondary`, `content.muted`, `status.error`, `status.warning`, `status.success` and `status.info` against a minimum of 4.5, then `outline` and `focus` against a minimum of 3. It then evaluates `content.primary` over `selection` and `content.inverse` over `accent.primary`, `accent.secondary` and `accent.tertiary`, each against 4.5. Each ratio is the unrounded [opaque contrast ratio](12-contrast.md) of the foreground over the background. A pair passes when its ratio is at least its minimum, with no tolerance. A missing or translucent opaque fallback fails the guard. The guard passes only when every pair passes; it then publishes all 40 [pair results](../schemas/theme-legibility-guard.schema.json) in order. Otherwise it fails with a diagnostic that names each failing pair and publishes no pair results. A failure is never repaired by adjusting a color.

The thresholds draw on [WCAG 2.2 text contrast](https://www.w3.org/TR/WCAG22/#contrast-minimum) and [non-text contrast](https://www.w3.org/TR/WCAG22/#non-text-contrast). The guard is a check of named opaque pairs in a theme source. It does not claim that rendered UI is accessible: a backend must still evaluate actual foreground and adjacent colors after material, treatment, state, transparency, and backdrop resolution as required by [the contrast contract](12-contrast.md). The [guard vectors](../conformance/themes/legibility-guard-vectors.json) record the results for both authored themes; they follow the [vector schema](../schemas/theme-legibility-guard-case.schema.json) and must match within `1e-9` absolute per ratio. The Rust reference exposes `resolve_legibility_guard` and `legibility_guard_pairs`.
