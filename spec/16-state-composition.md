# Semantic state composition (candidate, schema 0.1.0)

A validated [state set](14-interaction.md) composes into the seven semantic layers in [state-composition.schema.json](../schemas/state-composition.schema.json). The blueprint names availability, validation, selection, interaction, navigation, and base as conceptual layers. This contract adds activity for the canonical `busy` state, so busy remains independent of disabled and interaction states. Composition groups signals; it does not choose pigment, edge, mechanics, motion, or a winning state.

`disabled` belongs to availability; `error`, `warning`, and `success` to validation; `active`, `selected`, and `checked` to selection; `hover`, `pressed`, and `dragging` to interaction; `focused` to navigation; `busy` to activity; and `rest` to base. Every input state MUST appear exactly once in the output, with no inferred `enabled` or `rest`. Every layer MUST be present, even when empty. States within a layer follow the canonical order in [the state set contract](14-interaction.md). Their order is deterministic serialization, not precedence.

The composition operation MUST preserve simultaneous states across and within layers, including `disabled` with `busy` or validation states, and `rest` with other states. It MUST NOT infer component-specific incompatibilities or suppress a state because another is present. The [composition vectors](../conformance/states/composition-vectors.json) cover these cases and all canonical states. Later visual rules must define how layer signals affect each output channel and must not interpret this grouping as a rendering instruction.
