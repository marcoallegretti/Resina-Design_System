# Edge color on a known adjacent surface (candidate, 0.1.0)

The [edge contrast request](../schemas/edge-contrast-request.schema.json) receives opaque sRGB colors bound to the semantic `outline` and `outline.strong` roles, the actual opaque `adjacentColor` at one edge location, and a finite `minimumContrast` from 1 through 21. The caller determines which adjacent color and threshold apply to the edge's purpose. Resina does not infer a component, edge placement, width, state, renderer, or accessibility criterion from the role names. The operation is independent of a rendering backend.

The request MUST be a JSON object. Arrays and other non-object JSON values MUST be rejected diagnostically without a result.

All three colors MUST be valid opaque sRGB fallbacks. Unknown fields, invalid colors, unsupported versions, and nonfinite or out-of-range thresholds are errors. Duplicate JSON members MUST be rejected before object conversion. The resolver MUST calculate unrounded [opaque contrast](12-contrast.md) between `outline` and `adjacentColor`. If that ratio meets `minimumContrast`, it retains `outline`. Otherwise it tests `outline.strong` against the same adjacent color. If that meets the threshold, it selects `outline.strong`. If neither passes, it MUST fail diagnostically without a partial result. The resolver MUST NOT fabricate a color or silently weaken the threshold.

The [result](../schemas/edge-contrast-result.schema.json) reports the chosen semantic color role, its opaque color, the unrounded contrast ratio, and whether the strong fallback was applied. The [vectors](../conformance/color/edge-contrast-vectors.json) cover retention, fallback, equality at the threshold, insufficient contrast, and invalid input. `resina-edge-contrast <path|->` accepts one UTF-8 request file or standard input; success exits 0 with one strict JSON result and no diagnostic, failure exits 1 with no result and a diagnostic, and usage errors exit 2. Input is bounded to 1 MiB. The [external checker](../tools/check_edge_contrast_backend.py) verifies the public protocol and deterministic results.

This result chooses one edge color against one known adjacent color. It does not resolve edge geometry, width, depth, highlight, state-specific treatment, or visibility across a variable backdrop. An edge spanning different adjacent colors needs evaluation at the relevant locations. An edge may also need contrast with the interior color, depending on how it conveys information. The [W3C explanation of non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#adjacent-colors) distinguishes required component boundaries from decorative ones and explains how the adjacent color depends on placement. Passing this local operation alone does not establish WCAG conformance or complete Tier 0 surface appearance.
