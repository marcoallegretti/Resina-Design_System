# Opaque color fallback (candidate, schema 0.1.0)

An sRGB fallback may still be translucent. A surface resolved to an opaque representation needs an explicitly opaque color without assuming what lies behind it. This operation accepts one validated DTCG color value and an optional separately authored DTCG color value. It returns an [opaque sRGB fallback](../schemas/opaque-srgb-fallback.schema.json), or fails without a color. It is a color prerequisite for Tier 0; it does not derive material pigment, choose a surface representation, or guarantee contrast.

The resolver MUST first derive the source's [portable sRGB fallback](07-color-fallback.md), including its alpha. An invalid or nonportable source MUST fail even when an authored opaque fallback exists. If an authored value is present, the resolver MUST validate and convert it by the same sRGB fallback contract and require its resolved alpha to equal 1. The authored value wins even when the source is already opaque. If no authored value is present, an opaque source fallback is returned unchanged. A translucent source with no authored value MUST fail. The resolver MUST NOT composite against an assumed backdrop, discard source alpha, or infer an opaque fallback from `hex`, which does not carry alpha under the [DTCG Color Module 2025.10](https://www.designtokens.org/TR/2025.10/color/).

An [opaque color assignment](../schemas/opaque-color-assignments.schema.json) supplies a sparse role-to-token-path map with `schemaVersion` `0.1.0`. Its `roles` object MAY be empty, but every present key MUST be one of the semantic color roles and every path MUST be nonempty. The resolver checks every role in canonical role order. It uses the bound source color and, when the role has an authored path, requires that path to name a resolved DTCG `color` token. Missing paths, wrong types, invalid authored colors, and translucent sources without an authored path are diagnostic failures. It publishes a complete opaque fallback map only when all roles succeed. An authored path takes precedence even when the source is opaque; this permits a theme to provide a distinct Tier 0 tone. The [assignment vectors](../conformance/color/opaque-assignment-vectors.json) define structural validation.

The [color operation vectors](../conformance/color/opaque-fallback-vectors.json) cover opaque reuse, authored precedence, translucent source rejection, invalid source and authored values, and wide-gamut source fallback. The [headless resolution](19-headless-resolution.md) applies this operation to every semantic color role. Material pigment, edge, and contrast rules still need their own contracts before this output becomes render-ready IR. The Rust reference exposes `resolve_opaque_srgb_fallback` and `resolve_semantic_opaque_color_fallbacks` without a renderer dependency.
