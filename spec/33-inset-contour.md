# Bounded inset contours (candidate, 0.1.0)

Tier 0 edge and highlight bands need inspectable geometry. This operation consumes actual logical surface bounds, four logical elliptical corner radii, and one uniform inset in logical `px`. It does not choose a material, color, band width, key-light direction, content layout, or rendering primitive. A caller may use the region between outer and inner contours as an edge band, or another nested contour for a highlight band. Highlight placement still needs a lighting contract.

The [request](../schemas/inset-contour-request.schema.json) requires all fields and version `0.1.0`. Bounds, radii, and inset MUST be finite and nonnegative. Unknown or missing members and unsupported versions MUST fail. An inset greater than half either dimension MUST fail rather than silently shrink an authored width. Zero inset and zero-sized surfaces are valid. Equality with half a dimension produces a collapsed inner contour; a zero width or height encloses no inner area.

Resolution MUST first apply the [bounded-corner rule](09-geometry.md) to the outer radii. The inner dimensions are `width − 2 × inset` and `height − 2 × inset`, and its logical top and start offsets both equal `inset`. Each inner radius component is `max(0, normalizedOuterComponent − inset)`. Resolution MUST then apply the same bounded-corner rule to these inner radii using the inner dimensions. The [result](../schemas/inset-contour-result.schema.json) reports normalized outer radii, inset, inner size, and normalized inner radii. The original outer bounds remain supplied by the request.

Subtracting thickness follows the established [CSS corner shaping rule](https://www.w3.org/TR/2014/CR-css3-background-20140909/#corner-shaping). Resina additionally bounds the inner contour independently: asymmetric corners can otherwise overlap after insetting. This portable approximation is not an exact Euclidean offset of an ellipse and does not specify CSS box layout. A backend MUST preserve both contours; substituting a centered toolkit stroke can change the exterior bounds and is not equivalent. A radius with either component zero is a square corner. Logical start/end corners remain logical until the backend maps them using the actual writing direction.

All output dimensions and radii MUST remain finite and nonnegative, including near the maximum finite input. Results are compared with absolute tolerance `1e-12`, without relative tolerance. [Conformance vectors](../conformance/geometry/inset-contour-vectors.json) cover uniform, elliptical, asymmetric, normalized, sharp, collapsed, and zero contours, plus diagnostic failures. Rust typed calls validate the same numerical invariants as the source operation.

`resina-inset-contour <path|->` reads one UTF-8 request up to 1 MiB. Success exits 0 with one JSON result and no diagnostic; invalid input exits 1 with a diagnostic and no result; usage errors exit 2. Duplicate JSON members are rejected at every depth. The [external checker](../tools/check_inset_contour_backend.py) checks the source-to-result protocol and repeated output independently of Rust.

This is one geometry operation, not complete surface appearance or Resina IR. Edge color still requires its actual adjacent-color guard; an edge width is not inferred from that guard. Content placed within an inner contour needs separate layout and contrast decisions. Depth separation, key and ambient lighting, state response, and material anatomy remain distinct contracts.
