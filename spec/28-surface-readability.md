# Base-state surface readability (candidate, 0.1.0)

The request MUST be a JSON object. Positional arrays and other non-object roots are invalid.

The [request](../schemas/surface-readability-request.schema.json) combines one complete [surface scenario](21-surface-scenarios.md), an explicit semantic `foregroundRole`, the actual opaque sRGB `adjacentColor` at one edge location, and separate finite content and edge contrast thresholds in `[1, 21]`. Frost additionally requires the actual opaque sRGB `postTreatmentBackdrop` below its body; this field MAY be omitted for an opaque Cast, Elastomer, or Gel body. A present backdrop MUST be valid and opaque, including when the selected family does not use it. The operation does not infer a foreground from the material family or the theme's light/dark name. The caller MUST supply colors that describe the actual local surroundings. Unknown or varying surroundings require separate evaluation at each relevant location.

The bound state set MUST contain only `rest`, `focused`, or both, and the bound surface's final optical treatment MUST be `none`. The operation MUST preserve the complete supplied state set in canonical order; it MUST NOT add `rest` when only `focused` was supplied. Focus is an independent navigation channel: it MUST leave body, foreground and exterior surface-edge readability unchanged. A focused consumer MUST additionally resolve and display the separate [focus indicator](27-focus-indicator.md); this body result does not contain a navigation cue. Every other state MUST fail until its body appearance has a separate resolution contract. Ancestor treatments are permitted when their resulting backdrop is known and supplied for Frost. This operation does not invent active-state pigment, treatment rendering, content size, or component anatomy. It MUST reject duplicate JSON members, unsupported versions, invalid nested inputs, translucent surroundings, and out-of-range thresholds without publishing a partial result.

For Cast, Elastomer, and Gel, the body and foreground MUST come from the selected semantic roles' [opaque sRGB fallbacks](13-opaque-color-fallback.md). The resolver MUST calculate their unrounded [contrast ratio](12-contrast.md) and fail if it is below `minimumContentContrast`. It MUST NOT silently use a translucent source color, switch foreground roles, or assume a backdrop. The `contentFallbackApplied` field is false because the selected opaque fallbacks are the Tier 0 inputs, not a fallback triggered by this operation.

For Frost, the resolver MUST apply the existing [Frost surface readability](26-frost-surface-readability.md) operation to the same bound surface and semantic snapshot. Its foreground is the resolved portable sRGB color and MUST be opaque. Frost may retain its selected translucent body or fall back to `opaqueDimensional` according to the established legibility rule. The result MUST publish that final `frostRepresentation`, `body`, opaque `compositedBody`, unrounded `contentContrastRatio`, and `contentFallbackApplied`. The retained `binding` is the preliminary semantic binding; consumers MUST use the result's final body and representation when Frost falls back.

All four families MUST use the same snapshot's opaque `outline` and `outline.strong` roles with the [edge contrast](25-edge-contrast.md) operation against `adjacentColor` and `minimumEdgeContrast`. A content or edge failure publishes no result. The [result schema](../schemas/surface-readability-result.schema.json) constrains the family-specific output; the [cases](../conformance/surfaces/readability-cases.json) cover four families, Frost fallback, authored opaque foreground selection, contrast failures, unresolved states and treatments, invalid input, and duplicate-member rejection. `resina-surface-readability <path|->` reads one UTF-8 request up to 1 MiB and emits one JSON result with status 0, or a diagnostic with status 1 and no result; usage errors exit 2. The [external checker](../tools/check_surface_readability_backend.py) validates the public command protocol and deterministic output independently of the Rust library.

This operation establishes base-state content contrast and edge color contrast against the supplied exterior adjacency, not complete Tier 0 appearance or WCAG conformance. It does not test edge contrast against the surface body, choose edge width or placement, highlight, depth, shape geometry, motion, or contrast across a variable rendered backdrop. Required visual indicators must be assessed against their [actual adjacent colors](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html#adjacent-colors) after rendering.

Failure diagnostics follow the [public backend diagnostic policy](32-headless-conformance.md#failure-diagnostics). Negative public cases use `failure: true`; diagnostic wording is not a conformance requirement.
