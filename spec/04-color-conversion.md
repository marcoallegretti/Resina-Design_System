# sRGB, Oklab, and Oklch conversion (candidate)

Resina uses the [CSS Color Module Level 4 conversion sequence](https://www.w3.org/TR/2026/CRD-css-color-4-20260930/#color-conversion-code) pinned to the 30 September 2026 draft for conversion between encoded sRGB and D65 Oklab. This contract adopts the coefficients and transfer functions of its `lin_sRGB`, `gam_sRGB`, `lin_sRGB_to_XYZ`, `XYZ_to_lin_sRGB`, `XYZ_to_OKLab`, and `OKLab_to_XYZ` sample functions. Matrix rows multiply component columns in the order shown there. The reference implementation and [conformance vectors](../conformance/color/oklab-conversion-vectors.json) must agree with that sequence; no backend-specific color operation defines it.

The forward operation accepts exactly three finite encoded sRGB components in `[0, 1]` and returns Oklab `[L, a, b]`. The reverse operation accepts exactly three finite Oklab components and returns encoded extended-sRGB components. It MUST preserve out-of-gamut values instead of clipping or gamut mapping them. A nonfinite input, out-of-range forward input, or nonfinite result MUST fail explicitly. Alpha is independent of this three-component conversion and is carried separately by the caller. These operations do not choose a palette, pigment, interpolation rule, or output gamut mapping.

For Oklch `[L, C, h]` to Oklab, Resina adopts the pinned CSS `OKLCH_to_OKLab` polar conversion: `[L, C cos(hπ/180), C sin(hπ/180)]`. Input components MUST be finite, with `L` in `[0, 1]`, `C ≥ 0`, and hue in `[0, 360)` degrees, matching DTCG 2025.10 token ranges. Out-of-range input and nonfinite results MUST fail. A zero-chroma hue has no effect on the result. This operation does not interpolate hues or define the missing-component behavior of `none`. The [Oklch vectors](../conformance/color/oklch-conversion-vectors.json) cover axes, zero chroma, and invalid ranges.

An extended-sRGB result is not an [sRGB fallback](07-color-fallback.md) unless every channel is in `[0, 1]`. A producer that needs a portable fallback MUST apply a separately specified gamut-mapping rule or use an authored fallback; it MUST NOT silently clamp this result. This conversion is a headless color calculation and does not change semantic color assignments.
