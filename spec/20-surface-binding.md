# Headless surface binding (candidate, 0.1.0)

A [surface binding intent](../schemas/surface-binding.schema.json) selects one semantic material role, one semantic color role, one validated [surface form](09-geometry.md), and one validated [state set](14-interaction.md). It has no component identity, content, size, renderer name, or toolkit object. The roles name requested semantics; they do not name a material family or a numeric color. All five members are required under `schemaVersion` `0.1.0`; unknown members, roles, nested values, and versions are invalid.

Binding consumes an intent and one successful [headless semantic resolution](19-headless-resolution.md). It MUST select the material family from the requested material role, and both the DTCG source color and its portable sRGB fallback from the requested color role. It MUST preserve the form and the complete state set, normalized to canonical state order without choosing a winning state. When the selected family is Frost, it MUST attach the context's resolved Frost representation. For Cast, Elastomer, or Gel, it MUST omit that field. A missing role or fallback in the context is a diagnostic failure; no partial surface is published.

The [result schema](../schemas/surface-binding-result.schema.json) and [binding vectors](../conformance/surfaces/binding-vectors.json) define the inspectable output. The result keeps both role identities and bound values so later resolution can distinguish theme choice from source intent. This binding is not render-ready Resina IR: material pigment, edge, treatment fallback, state visuals, mechanics, motion, accessibility behavior, and component anatomy require their own contracts. A backend MUST NOT treat a bound surface as permission to invent those missing decisions.
