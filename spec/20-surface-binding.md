# Headless surface binding (candidate, intent 0.2.0, result 0.4.0)

The intent MUST be a JSON object. `materialRole` and `colorRole` MUST use the
string forms defined by the schema. Positional records and object-encoded roles
are invalid, including when decoded through the shared intent type.

A [surface binding intent](../schemas/surface-binding.schema.json) selects one semantic material role, one semantic color role, one validated [surface form](09-geometry.md), one validated [state set](14-interaction.md), and one validated [optical treatment stack](06-optics.md). It has no component identity, content, size, renderer name, or toolkit object. The roles name requested semantics; they do not name a material family or a numeric color. All six members are required under `schemaVersion` `0.2.0`; unknown members, roles, nested values, and versions are invalid. The [0.1.0 intent schema](../schemas/versions/surface-binding-0.1.0.schema.json) remains available to migration tooling; a previous intent needs an explicitly chosen treatment stack before it can be used as 0.2.0.

Binding consumes an intent and one successful [headless semantic resolution](19-headless-resolution.md). It MUST select the material family from the requested material role, and the DTCG source color, portable sRGB fallback, and opaque sRGB fallback from the requested color role. It MUST preserve the form, the complete state set normalized to canonical state order without choosing a winning state, and the treatment stack in its authored ancestor order. The stack's final treatment applies to the bound surface; preceding treatments describe ancestors. When the selected family is Frost, binding MUST attach the context's resolved Frost representation and the [`frostPortableBody` color](31-fallback.md) selected by that representation and tint strength. For Cast, Elastomer, or Gel, it MUST omit both Frost fields. A missing role or fallback, or an invisible translucent Frost body, is a diagnostic failure; no partial surface is published.

The [result schema](../schemas/surface-binding-result.schema.json) and [binding vectors](../conformance/surfaces/binding-vectors.json) define the inspectable output. The [0.3.0](../schemas/versions/surface-binding-result-0.3.0.schema.json), [0.2.0](../schemas/versions/surface-binding-result-0.2.0.schema.json), and [0.1.0](../schemas/versions/surface-binding-result-0.1.0.schema.json) result schemas remain available to migration tooling. The result keeps both role identities and bound values so later resolution can distinguish theme choice from source intent. A separate [edge contrast operation](25-edge-contrast.md) can select an authored outline color against one known adjacent color; it does not complete edge styling. After an opaque body has been selected, the [opaque pigment operation](29-opaque-pigment.md) can derive its side and highlight colors. This binding is not render-ready Resina IR: edge geometry, highlight placement, depth separation, treatment fallback, state visuals, mechanics, motion, accessibility behavior, and component anatomy require their own contracts. A backend MUST NOT treat a bound surface as permission to invent those missing decisions.
